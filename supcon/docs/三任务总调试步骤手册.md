# 中控杯赛题 2：三个任务总调试步骤手册

> 适用工程：`supcon/`  
> 任务接口：`/api/task1/execute`、`/api/task2/execute`、`/api/task3/execute`  
> 原则：**先设备安全，再单点动作，再任务闭环，最后接入比赛软件。**  
> 禁止事项：未通过 `plan_only`、未确认手型、未确认相机画面方向时，不执行贴近面板、物体或槽位的正式动作。

---

## 0. 最终目标与规则基线

| 任务 | 目标 | 关键规则 |
|---|---|---|
| Task1 | 根据随机亮灯，操作下方对应按钮或拨动开关 | 共 3 次独立调用；2 按钮 + 1 拨动开关 |
| Task2 | 将 4 个数字长方体按 1→2→3→4 放上指定台面 | 数字**仅顶面**可见；放置姿态与初始槽内一致 |
| Task3 | 将 4 个几何体放入对应形状名称槽位 | 更新后道具**全部竖直摆放**；主体必须完全入槽 |

三个任务都以“无碰撞、无掉落、无工装移位”为最高优先级。出现视觉低置信、设备错误或规划回退时，系统应回安全位并返回失败，不得猜测继续。

## 2. 三任务共用的设备调试

### 2.1 网络与服务连通性

确认 B9 与 O10 的真实 IP 后，修改 `config/config.yaml`：

```yaml
arm:
  base_url: "http://<B9_IP>:8087"
  arm: "right_arm"       # 若现场为左臂，改为 left_arm
  pose_key: "right"      # 左臂对应 left

hand:
  base_url: "http://<O10_IP>:8088"
```

执行：

```bash
curl http://<B9_IP>:8087/api/motors
curl http://<B9_IP>:8087/api/pose
curl http://<O10_IP>:8088/api/status
curl http://<O10_IP>:8088/api/errors
```

验收：

- [ ] B9 所有关节 `fault=0`、`has_feedback=1`，反馈年龄正常。
- [ ] O10 `connected=true`，全部 `error_codes=0`。
- [ ] B9 `/api/pose` 不为 `null`。
- [ ] 已确认现场使用右臂或左臂，`arm` 与 `pose_key` 配置一致。

### 2.2 灵巧手手型与 TCP 确认

```bash
python scripts/01_hand_semantics.py
```

根据实测修改 `hand.open_pose`、`hand.close_pose`、`hand.point_pose`。不要依赖文档中 0/1 的张开/闭合文字描述。

现场必须完成：

- [ ] 确认 `open_pose` 真正张手，`close_pose` 真正闭合。
- [ ] 确认 `point_pose` 时食指可操作按钮，其他手指不会撞面板。
- [ ] 固定 `point_pose` 后，测量 B9 控制末端到真实食指尖的偏移；所有 Task1 示教在该手型下完成。
- [ ] 为 Task2/3 的不同物体录制安全抓取手型，记录在各自 JSON 的 `hand_grasp` 或 `default_hand_grasp`。

### 2.3 相机与画面方向确认

修改：

```yaml
camera:
  mode: "real"
```

分别在面板观察位、Task2 观察位、Task3 观察位采图，人工检查：

- [ ] 彩色流画面正常，无偏色、乱码或错误像素格式。
- [ ] 图像没有镜像/旋转；若存在，先在相机层修正，再标 ROI。
- [ ] 每个观察位都能完整看见其目标区域，且手和相机支架不遮挡。
- [ ] 赛场光照下反光、阴影、自动曝光不会遮蔽数字、灯或物体边缘。

### 2.4 安全位与直线规划

1. 在机械臂远离工装的净空位置记录 `arm.safe_pose`。
2. 用 `scripts/02_record_pose.py --where` 获取观察位和动作位。
3. 每一个候选位姿都先做 `plan_only` 校验。

```bash
python scripts/02_record_pose.py --goto <x> <y> <z> <roll> <pitch> <yaw>
```

验收：

- [ ] 所有关键位姿都可直线规划。
- [ ] 正式响应不含 `OMPL`；出现 OMPL 必须重新示教，不接受自由路径回退。
- [ ] 下降、上升、撤离均留有足够净空，手指、相机和线缆不碰工装。
- [ ] 已确认实体急停位置和现场人员处置流程。

## 3. Task1 调试：亮灯后的拨按开关

### 3.1 建立“灯 → 开关”显式映射

在观察位拍到清晰面板图后：

```bash
python scripts/03_calibrate_panel.py --mode manual
```

脚本按画面左到右写入 `config.yaml` 的 `task1.panel.lamps`。随后确认每盏灯的真实 `switch_id`；不要因为画面顺序相同就省略映射。

```json
{
  "lamps": [
    {"id": 0, "switch_id": 2, "cx": 200, "cy": 240, "roi_radius": 18}
  ]
}
```

### 3.2 记录亮灯基线

确保三盏灯均熄灭、相机位姿固定：

```bash
python scripts/03_calibrate_panel.py --save-baseline
```

- [ ] `config.yaml` 的 `task1.panel` 含 `baseline_scores`。
- [ ] 分别点亮三盏灯，连续采样确认均能稳定识别。
- [ ] 调整 `lamp_abs_min`、`lamp_margin`，直到环境反光下也不误判。

### 3.3 示教两个按钮和一个拨动开关

每个按钮示教：

```bash
python scripts/02_record_pose.py --switch <id> --key approach_pose
python scripts/02_record_pose.py --switch <id> --key press_pose
```

拨动开关示教：

```bash
python scripts/02_record_pose.py --switch <id> --key approach_pose
python scripts/02_record_pose.py --switch <id> --key flick_start_pose
python scripts/02_record_pose.py --switch <id> --key flick_end_pose
```

验收：

- [ ] 确认两个开关的 `type=button`，一个开关的 `type=toggle`。
- [ ] 按钮行程、停留时间和退出高度已逐个验证。
- [ ] 拨杆的起点、终点与拨动方向已在实物上验证。
- [ ] 所有记录位姿均在 `point_pose` 下完成。

### 3.4 单任务闭环

```bash
python scripts/05_test_task1.py
```

依次让每盏灯亮一次，检查程序是否操作了 `switch_id` 指向的正确开关。若现场确认成功动作会改变对应灯状态，可设置：

```yaml
task1:
  action_verify: "lamp_change"
```

否则保留 `motion_only`，避免因规则未承诺的灯状态变化而误报失败。

Task1 上场门槛：

- [ ] 三盏灯分别测试至少 10 次，识别与开关映射零错误。
- [ ] 每种按钮/拨杆动作连续 10 次无碰撞。
- [ ] 三次连续调用均从安全位开始并正确完成。

## 4. Task2 调试：顶面数字长方体有序转运

### 4.1 顶面数字识别（整图 OCR）

数字只在顶面；必须采用俯视观察位，一次拍全 4 个源槽位。

1. 观察位拍一张顶视图，整图送入 OCR，按文本框 x 坐标左→右读出 4 个数字，依次对应方位 `left → midleft → midright → right`。**无需 ROI、无需数字模板**。
2. 现场光照下连续识别，确认能稳定读出恰好 `{1,2,3,4}`。

验收：

- [ ] 任意槽位的顶面数字均可被识别。
- [ ] 识别结果恰好是 `{1,2,3,4}`，不重复、不缺失。
- [ ] 读不出或读错时系统返回失败，不会猜测顺序。

### 4.2 示教抓放位姿

每个源槽位填写：

- `approach_pose`：物体上方安全高度；
- `grasp_tcp_pose`：实际抓取 TCP 位；
- `lift_pose`：抓起后竖直上升位。

全局抓取手型填 `default_hand_grasp`（Task2 的 4 块长方体同尺寸，独立于 Task3；用 `08` 脚本 `--record-task2-grasp` 录制、`--apply-task2-grasp` 回放校验），也可在某槽位用 `hand_grasp` 覆盖。

在 `table_placements` 中为 1–4 分别填写台面上的：

- `approach_pose`；
- `place_pose`；
- `retreat_pose`。

放置 RPY 必须与物块在初始槽位时的竖直姿态一致；四个放置位都必须在指定台面边界内。

### 4.3 场景预检与闭环

```bash
python scripts/07_validate_scene.py --task 2 --plan-only
```

随后调用：

```bash
curl -X POST http://127.0.0.1:5000/api/task2/execute \
  -H 'Content-Type: application/json' -d '{}'
```

按以下顺序验收：

- [ ] 只从顶面识别数字。
- [ ] 日志显示严格 1→2→3→4。
- [ ] 每次抓取后物块稳定抬起，未掉落。
- [ ] 每个物块放在指定台面，竖直且姿态正确。
- [ ] 连续完成 20 次，顺序零错误、无碰撞。

## 5. Task3 调试：竖直几何体分拣

### 5.1 现场类别—槽位映射

赛题只保证槽外有形状名称标识，未规定文字格式。不要依赖 OCR 读取槽位文字；在现场人工确认后，将真实类别写到 `config.yaml` 的 `task3.scene.destinations` 键中。

Task3 不再为源物体填写固定工位或抓取坐标。应在 `config.yaml` 的 `task3.scene` 填写唯一的全局
`observe_pose`、桌面 `workspace_roi`、深度分割阈值、四个槽位和各形状手型。木块
XY 从 Gemini335 的同帧对齐 RGB-D 实时计算；没有 `T_eef_camera` 与实际抓取 TCP 的
`T_eef_tcp` 标定时，任务会在使能前安全失败。

### 5.2 分类调试

当前代码先用深度 RANSAC 分割桌面和凸出物，再使用顶面轮廓圆度、近似顶点数分类。现场按以下顺序调试：

1. 确认道具均为竖直姿态；不做旧版 6-DOF 翻转。
2. 在全局观察位抓图，缩小 `workspace_roi`，确认槽位和白色工装没有进入主要轮廓。
3. 验证圆柱、长方体/正方体、棱柱/多面体的分类输出。
4. 若轮廓不稳定，优先调 ROI、桌面平面阈值和最小面积；不要降低置信度阈值或改回固定坐标。

### 5.3 示教入槽位姿

每个 `destinations.<shape>` 都需要：

- `approach_pose`：槽口正上方；
- `place_pose`：物体主体完全进入槽位的竖直位置；
- `retreat_pose`：松手后的安全撤离位。

所有位置均应低速直线进入；不能用末端碰撞、灵巧手堵转来代替槽底高度标定。

### 5.4 场景预检与闭环

```bash
python scripts/07_validate_scene.py --task 3 --plan-only
curl -X POST http://127.0.0.1:5000/api/task3/execute \
  -H 'Content-Type: application/json' -d '{}'
```

Task3 上场门槛：

- [ ] 四个类别均映射到正确槽位。
- [ ] `T_eef_camera`、`T_eef_tcp` 已多点反投影和低速试抓验证。
- [ ] 全局检测与预抓复拍均稳定检测到 4 件不同形状木块。
- [ ] 物体始终竖直抓取、竖直放置。
- [ ] 每件物体完全入槽，不悬边、不压线、不掉落。
- [ ] 至少连续 20 次，分类与槽位映射零错误。

## 6. 三任务联调与比赛软件接入

启动服务：

```bash
python scripts/06_serve.py
```

健康检查：

```bash
curl http://127.0.0.1:5000/api/health
```

返回必须为：

```json
{"success": true, "message": "ready"}
```

若返回 `success=false`，先修复机械臂/灵巧手连通性，不要在竞赛软件中开始任务。

联调顺序：

1. Task1：用三盏不同亮灯各调用一次。
2. Task2：核对日志顺序为 1→2→3→4。
3. Task3：核对每个分类结果与实际槽位标签一致。
4. 三项任务分别连续执行两遍；每一遍结束后检查机械臂回安全位、灵巧手张开、无错误码。
5. 在竞赛软件填写 Base URL，例如 `http://127.0.0.1:5000`，再使用软件调用三项接口。

## 8. 异常处置原则

| 现象 | 立即动作 | 后续处理 |
|---|---|---|
| 灯/数字/形状低置信 | 停止当前任务并回安全位 | 调 ROI、基线、模板或光照，不猜测 |
| B9 返回 OMPL 或不可达 | 不执行贴近工装动作 | 重新示教位姿或调整安全高度 |
| 手过流、过热、通讯异常 | 停止后续动作，按现场安全流程处置 | 清除错误、重新健康检查 |
| 抓空或掉落 | 张手、撤离 | 重新观察并检查手型/抓取高度 |
| 物体未完全入槽/未在台面 | 不盲目二次下压 | 重新标定 `place_pose` 和撤离高度 |
| 任意疑似碰撞 | 现场实体急停优先 | 通知工作人员，检查设备后再继续 |
